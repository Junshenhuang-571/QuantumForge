A repeatable path through a local experiment

Keep the circuit, transformation choices, and noise assumptions visible. Use the outputs to understand a run and reproduce it—not as a substitute for hardware calibration.

01 / Design

Start from a circuit

Build with the Rust or Python API, use the interactive REPL, or import supported OpenQASM 2 circuits.

02 / Compare

Inspect transformations

Apply rewrite passes, route against a topology, check supported target constraints, and save resource and run details.

03 / Study

Make noise explicit

Simulate density matrices with T1/T2-derived thermal noise, including idle periods when operation timings are supplied.

Tools for quantum research

A broad research library, not a single-purpose compiler. Pick the parts that fit your experiment and work locally.

Symbolic Algebra

PauliSum, ExactComplex, and Rational support exact arithmetic for supported expressions. Circuit simulation and VQE use floating-point numerics.

Interactive REPL

Build circuits incrementally, inspect the live state, draw circuit diagrams, and sample measurements with a reproducible seed.

Circuit Optimization

Apply rewrite passes, route against a topology, check declared native-gate and directed-CNOT constraints, and save a JSON report. General basis translation, global layout search, and hardware submission are not implemented. See the compiler roadmap.

Density Matrices

Density-matrix simulation with explicit channels and a T1/T2-based thermal model. Schedule-aware idle noise uses timings supplied by the caller; the model is not a hardware calibration feed.

Variational / QML

ParameterizedCircuit with data encoding, parameter-shift, adjoint, backpropagation, and finite-difference gradient methods, plus Adam trainers for regression and classification.

Shot-Aware VQE

A research implementation of SubsCoRe-style adaptive shot allocation for variational optimization, with a reproducible total-shot-budget workflow.

CUDA Backend

Optional acceleration for selected simulation paths. CUDA/GPU features require a compatible NVIDIA toolkit and are not part of the default CPU install.

Python Bindings

An abi3 wheel exposing circuits, states, QEC, tensor networks, gradient strategies, exact-rational tools, and SubsCoRe. Browse the current surface in python/API.md.

LLVM JIT

Lower supported scalar numeric expressions to LLVM IR and JIT-compile them. This is not a quantum-circuit compiler.

Clear scope builds trust

QuantumForge is early-stage software. The platform comparison and proposed product direction are documented openly.

What works today

  • Local circuit simulation, measurement, and research algorithms
  • Rust library and CLI, plus a Python binding surface
  • Small-circuit optimization checks and explicit model-based noise
  • Open-source Apache-2.0 project

What is still missing

  • General device layout and native-gate translation
  • Calibration-aware optimization and schedule generation
  • Working provider discovery, job submission, and result retrieval
  • External usage and customer evidence for a paid product

Read the sourced platform comparison and commercial hypotheses before treating the roadmap as a product claim.

Library Usage

use quantumforge::{Circuit, StateVector, parse_circuit};

// Build from a Wolfram-style expression, or the builder API.
let circuit = parse_circuit("Circuit[H[0], CNOT[0,1], Measure[0,0]]").unwrap();
let initial = StateVector::zero(2).unwrap();
let result = circuit.run_shots(&initial, 1000, 42).unwrap();
println!("{:?}", result.counts);

Python

The same kernel from Python. Full reference: python/API.md · install and examples: python/README.md.

from quantumforge import Circuit, StateVector

circuit = Circuit()
circuit.add_gate("H", 0)
circuit.add_cnot(0, 1)
print(circuit.run(StateVector.zero(2)).probabilities())
# [0.5, 0.0, 0.0, 0.5] — float: 0.5000000000000001

CI

Pushes to main and pull requests targeting main run formatting, lint, build, and test checks on Ubuntu, Windows, and macOS, plus separate MSRV, optional-feature, and security jobs. A Qiskit comparison job checks a defined optimizer subset on Ubuntu. These checks do not establish broad compiler parity or hardware performance.
